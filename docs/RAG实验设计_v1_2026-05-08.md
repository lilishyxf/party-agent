## 摘要

本实验设计旨在评估党务 Agent 的 RAG(检索增强生成)系统性能,
通过"基线测试 → 分批入库 → 重测对比 → 切片优化 → 重测对比"的对照实验流程,
量化每一步系统改进对最终问答准确率的影响,
为系统迭代提供数据支撑,为答辩提供量化证据。

---

## 一、实验目标

### 主目标
量化"知识库扩充"和"切片优化"两类工程动作对 RAG 系统问答准确率的贡献。

### 次目标
- 识别系统当前的性能瓶颈(检索召回 / 切片质量 / 模型推理 / 提示词)
- 为后续 Day 8+ 的 Chatflow 优化提供数据驱动的改进方向
- 沉淀一套可复用的 RAG 系统评估框架(论文工程价值)

### 不在本实验范围内
- 自研层次化 RAG 算法的评估(留到 Day 30-58 单独实验)
- 写作模块的输出质量评估(留到 Day 25-40 单独实验)
- 多模型对比(本实验固定使用 DeepSeek V4 + MiniMax Embedding)

## 二、实验设计

### 2.1 实验对象

**测试集**:党务 Agent 测试问题集 v1(2026-05-07)
- 30 题,分四类:
  - A 类(条款查询)10 题:期望基准 ≥80%
  - B 类(概念理解)10 题:期望基准 ≥70%
  - C 类(流程操作)5 题:期望基准 ≥60%
  - D 类(边界陷阱)5 题:期望基准 ≥40%

**待评估系统**:Dify Chatflow + DeepSeek V4 + MiniMax Embedding + Qdrant 向量库

### 2.2 实验变量

| 实验阶段 | 自变量(改动) | 因变量(测量) |
|---|---|---|
| E0 基线 | 无改动,使用现有知识库 | 30 题准确率(总体 + 分类) |
| E1 入库 1 | 加入《党员网络行为规定》 | 准确率变化 |
| E2 入库 2 | 加入《八项规定实施细则》 | 准确率变化 |
| E3 入库 3 | 加入《党史学习教育工作条例》 | 准确率变化 |
| E4 入库 4 | 加入西工大学院文档 | 准确率变化 |
| E5 切片优化 | 切片大小 / 重叠率 / Rerank | 准确率变化 |

### 2.3 实验流程

```
E0 基线测试
   ↓ (期望:23-40% 准确率)
E1 加入《党员网络行为规定》
   ↓ (期望:覆盖 A 类 4 题,准确率 +10-15%)
E2 加入《八项规定实施细则》
   ↓ (期望:覆盖 A 类 3 题,准确率 +8-12%)
E3 加入《党史学习教育工作条例》
   ↓ (期望:覆盖 A 类 2 题,准确率 +5-8%)
E4 加入西工大学院文档
   ↓ (期望:覆盖 A 类 1 题,准确率 +3-5%)
E5 切片优化 + Rerank
   ↓ (期望:整体 +5-10%,主要提升 B/C 类)
最终结果 (期望:65-80% 准确率)
```

### 2.4 控制变量

为了保证实验对照的有效性:

| 控制项 | 取值 |
|---|---|
| LLM 模型 | DeepSeek V4(固定) |
| Embedding 模型 | MiniMax(固定) |
| Top-K 召回数 | 5(固定,先不调) |
| Chatflow 提示词 | 当前版本(固定,先不调) |
| 测试集版本 | v1(固定,**整个实验全程不变**) |

> **关键纪律**:测试集在实验过程中**绝对不能修改**——一旦改了,前后数据无法对比。
> 如果发现题目有问题,记下来(下一版 v2 改),但本轮实验沿用 v1。

### 2.5 评分标准

每题三档评分:
- **完全对** (1 分):答案正确 + 出处指向同一份文件
- **部分对** (0.5 分):答案大致正确但出处错 / 答案有遗漏
- **错** (0 分):答案错误 / 答非所问 / 答"不知道"

**总分计算**:加权求和 / 30 = 准确率%

> 评分由我(于笑非)人工进行,避免 LLM 评分偏差。每次评分留存 markdown 记录。

## 四、技术实现细节

### 4.1 Dify API 测试脚本要求(给 Claude Code 的工作指令)

**输入**:
- 读取 `outputs/党务Agent_测试问题集_v1_2026-05-07.md`
- 解析出 30 题(每题:题号、类别、题面、标准答案、出处)

**处理**:
- 逐题调用 Dify Chatflow API(POST 请求)
- API endpoint 和 API key 由用户在脚本运行时通过命令行参数或 `.env` 传入
- 每题间隔 2 秒(避免触发限流)
- 失败重试 3 次,记录失败项

**输出**:
- 落档到 `outputs/E{N}_测试结果_YYYY-MM-DD.md`
- markdown 表格字段:
  | 题号 | 类别 | 题面 | 标准答案 | 出处 | Dify 实际回答 | Dify 引用来源 | 评分(待人工) | 备注 |

**安全约束**:
- API key **绝对不能写进代码或落档**——`.env` 或环境变量
- 落档的 markdown 文件中**不得出现 API key**

### 4.2 入库操作要求

每次入库一份文档时,记录:
- 文档名 / 文件大小 / 入库时间
- Dify 知识库切片配置(切片长度 / 重叠 / 分隔符)
- 入库后切片数量

落档到 `outputs/入库日志_YYYY-MM-DD.md`(累积式,不覆盖)

### 4.3 切片优化实验(E5)的具体方案

| 配置组 | 切片长度 | 重叠 | 是否启用 Rerank |
|---|---|---|---|
| 默认 | 500 | 50 | 否 |
| 配置 A | 300 | 30 | 否 |
| 配置 B | 800 | 80 | 否 |
| 配置 C | 500 | 50 | 是(BGE-Reranker) |
| 配置 D(最优) | 待定 | 待定 | 待定 |

每组配置跑完整 30 题,选准确率最高的作为 Day 7 后的固定配置。

## 五、风险与应对

### 风险 1:基线分数过低导致全员错答,看不出差异
**应对**:基线低不是问题,只要 E1-E4 每一步有可观测的提升即可。
如果 E1 入库后**完全没提升**,说明检索系统有 bug(例如 Embedding 没生效),
立刻停止实验,排查系统而非继续推进。

### 风险 2:某一类题在所有配置下都答不对
**应对**:这是有价值的发现——记录下来,作为 Day 8+ Chatflow 优化的输入。
例如 D 类(边界陷阱)如果全错,说明需要在 Chatflow 提示词里加入"逐字核对约束"环节。

### 风险 3:测试集中题目本身有错
**应对**:记录下来,出 v1.1 修订版,**但本轮实验仍用 v1 跑完**(保持对照性)。
v1.1 留到下一轮实验用。

### 风险 4:DeepSeek API 限流或不稳定
**应对**:脚本里加重试机制 + 失败队列。如果某次 30 题里有 3+ 题因 API 失败,
该轮实验作废,重跑。

### 风险 5:工作量超预期
**应对**:E5 切片优化实验最多跑 4 组配置,跑完就停。
跑完一轮发现还有提升空间也不要追加——留到 Day 30-58 自研 RAG 算法时一起优化。
