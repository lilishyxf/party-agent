## 摘要

本文档梳理工业界与学术界(截至 2025 年)对 RAG(检索增强生成)系统的检索增强方法,
按"在 RAG 流程哪一段动手"分为五个阶段,每个阶段列出主流技术、对应解决的问题、
工业验证收益。文档不引入自创方法,所有列举均为已发表论文或开源项目实现。

文档配套一份"对照党务 Agent 当前痛点的优先级表",作为 E5 系列实验设计的依据。

## 一、整体框架:RAG 流程的五个可优化阶段

```
[原始文档]
   │
   ① 入库前优化  ── 切片策略 / 结构化解析 / 上下文增强
   ▼
[切片入库到向量库]
   │
   ② 查询前优化  ── 用户问题改写 / 扩展
   ▼
[用 query 去检索]
   │
   ③ 检索时优化  ── 用什么方法找、几路、怎么找
   ▼
[召回 Top-K 候选切片]
   │
   ④ 检索后优化  ── 重排 / 过滤 / 压缩
   ▼
[喂给 LLM]
   │
   ⑤ 生成时优化  ── Prompt 工程 / 强制采纳约束
   ▼
[最终回答]
```

**关键认知**:RAG 不是一个单点优化问题,任何一个阶段的薄弱环节都能拖垮整体准确率。
工业界最优做法是**多阶段组合**(典型组合:Hybrid Search + Reranker + Strict Prompt)。

## 二、① 入库前优化(切片 & 元数据)

### 2.1 切片策略谱系

| 技术 | 干什么 | 治什么病 | 实现复杂度 |
|---|---|---|---|
| **Naive Chunking** | 按固定字数切(如 500 字) | (基线) | 低 |
| **Recursive Chunking** | 优先按 \n\n → \n → 。逐级切 | 切片更自然,不破句 | 低 |
| **Semantic Chunking** | 用 embedding 找语义跳变点切 | 切片内主题更聚焦 | 中 |
| **Structure-aware Chunking** | 用 LLM 抽目录,按章/节/条切 | 法规、合同类结构化文档专用 | 中-高 |
| **Parent-Child Chunking** | 小块召回,返回大块给 LLM | "精确召回 vs 上下文丰富"的矛盾 | 中 |
| **Contextual Retrieval**(Anthropic 2024) | 给每个切片附加一段 LLM 生成的上下文摘要再 embedding | 切片脱离原文后丢失上下文 | 高(每个切片要过一次 LLM) |

### 2.2 元数据增强

为每个切片附加结构化标签(章节号、文档类型、关键词、出处),
检索时可按元数据过滤,显著提升精确度。

党务 Agent 场景的元数据建议:
- `doc_type`: 党内法规 / 西工大制度 / 教育部政策 / 业务字段
- `source_doc`: 出自哪份文件
- `clause_no`: 第几条第几款
- `concept_tag`: 涉及哪个概念(如"组织生活会""发展党员")

### 2.3 跟当前痛点的关系

党务 Agent 当前用的是 Dify 默认 Naive Chunking + 无元数据。
**升级到 Structure-aware + 元数据增强是 Day 30+ 自研层次化 RAG 的核心动作**
(对应决策 1.6 的子模块 1+2+3)。

**Day 3-7 不动这一层**——工程量大,收益不直接,且跟自研算法重叠。

## 三、② 查询前优化(Query 改写)

| 技术 | 干什么 | 治什么病 |
|---|---|---|
| **Query Rewriting** | 用 LLM 把口语化问题改写成更接近文档语言的查询 | 用户口语 vs 文档书面语的鸿沟 |
| **Query Expansion** | 一个问题生成多个相关问题,各跑一次检索,结果合并 | 单查询召回不全 |
| **HyDE**(Hypothetical Document Embedding) | 先让 LLM 假设性回答,用这个假回答 embedding 检索 | query 和 doc 的语义鸿沟 |
| **Multi-Query / RAG-Fusion** | 生成 N 个 query 变体,N 路检索结果用 RRF(Reciprocal Rank Fusion)合并 | 提升召回率,治"空答" |
| **Query Decomposition** | 复杂问题拆成多个子问题分别检索 | 多跳问题(如 C5"从申请到正式党员的所有阶段") |

### 党务 Agent 场景的典型场景

- 用户问"书记 0 次党课违规吗" → 改写成"党支部书记每年党课次数要求"(query rewriting)
- 用户问"民主评议和组织生活会区别" → 拆成"民主评议党员定义"+"组织生活会定义"+"二者对照"三路检索(Multi-Query)

**收益估计**:+5-15 个百分点。

## 四、③ 检索时优化(检索方法)

### 4.1 检索方法谱系

| 技术 | 干什么 | 治什么病 |
|---|---|---|
| **Dense Retrieval** | 向量检索,你现在用的 MiniMax | 语义相似检索的标配 |
| **Sparse Retrieval / BM25** | 经典 IR,精确匹配关键词 | 数字、条款号、专有名词 |
| **Hybrid Search** | BM25 + Dense 同时跑,RRF 合并 | 工业界最稳的提升手段 |
| **Graph Retrieval / GraphRAG** | 把文档变成知识图谱,沿关系跳着检索 | 多跳推理 |
| **Late Interaction / ColBERT** | token 级别晚期交互匹配 | 比 dense 精,比 cross-encoder 快 |

### 4.2 工业界验证数据

- 金融问答基准(arXiv 2506.01733):**Hybrid + Rerank 把 Recall@5 推到 0.816**,
  比单方法提升一大截
- 多个研究发现:**BM25 在含具体数字/编号的查询上经常打败 dense embedding**——
  对应党务 Agent 的 A4/A5(八项规定数字题)、A6/A7(条例条款题)

### 4.3 换 Embedding(同属本阶段,但是替换不是叠加)

| Embedding | 特点 |
|---|---|
| **OpenAI text-embedding-3** | 通用,英文强 |
| **MiniMax embedding**(当前) | 中文通用 |
| **BCEmbedding**(bce-embedding-base_v1) | 中文 RAG 专用,双语 + 跨语种 |
| **BGE 系列**(BAAI) | 中文 RAG 主流开源 |
| **M3E / GTE** | 国产开源 |

**关键认知**:换 embedding 是阶段 ③ 内部的替换,
**收益通常不如加 Hybrid Search + Reranker 大**。

## 五、④ 检索后优化(重排 & 压缩)

### 5.1 重排器(Reranker)

| 技术 | 干什么 | 工业验证收益 |
|---|---|---|
| **Cross-Encoder Reranker**(BCE-Reranker、BGE-Reranker、Cohere Reranker) | 召回 Top-20 后用更精的模型重排 Top-5 | 金融问答:正确率 33.5% → 49.0%,**+15.5 个百分点**(arXiv 2603.16877) |
| **LLM Reranker** | 直接让 LLM 当 rerank 评分员 | 精度最高但贵 |
| **RankLLaMA**(神经重排) | 专门训练的重排大模型 | MAP 从 0.523 → 0.797,+52% 相对提升(但延迟从 1.74s → 84s 每题) |

### 5.2 检索后处理的其他技术

| 技术 | 干什么 |
|---|---|
| **Contextual Compression** | 每个召回切片用 LLM 压缩,只留跟 query 相关的部分 |
| **Retrieval Filtering** | 按元数据过滤(只在特定文档集里搜) |
| **CRAG**(Corrective RAG) | 召回后先让 LLM 评估检索质量,差就触发重检索或上 web search |

### 5.3 Reranker 的代价

精度上去了,延迟也上去了。LiveRAG 2025 基准:
**RankLLaMA 把每题延迟从 1.74 秒推到 84 秒**——生产环境必须权衡。

党务 Agent 建议:**用轻量 cross-encoder(BCE-Reranker / BGE-Reranker-base)**,
不上 RankLLaMA 这种重型选手。

## 六、⑤ 生成时优化(治"模型不采纳")

这是 RAG 的最后一公里,也是**最便宜**的一段——只改 Prompt,不动检索栈。

| 技术 | 干什么 | 治什么病 |
|---|---|---|
| **Strict Grounding Prompt** | Prompt 强制"只用提供的上下文回答,上下文没有就说不知道,不许用常识" | 治"模型守预训练权重不采纳知识库"(即党务 Agent E4.3 的 D1/C3/D3) |
| **Citation-required Prompt** | 强制每句话标出处,模型才不敢瞎编 | 治"无引用" + 治幻觉 |
| **CRAG**(Corrective RAG) | 召回后让 LLM 评估检索质量 | 检索可信度低时的兜底 |
| **Self-RAG** | 模型自己决定要不要检索、检索几次、采不采纳 | 灵活但复杂 |

### 党务 Agent 当前最缺这一层

E0-E4.3 五轮实验暴露的典型 B 层问题:
- D1 培养联系人投票:知识库有 KP-3.4 明确规定,但模型答"支委当然能投票"
- C3/D3 6 项议程顺序:知识库 KP-1.4 明确规定顺序固定,但模型答"可调整"

**这些不靠改 RAG 治,靠改 Prompt 治**——而 Prompt 改动**工时 1 小时,
收益预期 +5-10 个百分点**,是性价比最高的优化点。

## 七、对照党务 Agent 当前痛点的方法优先级

### 7.1 痛点 → 治本方法对照

| 痛点编号 | 现象 | 病灶 | 治本方法 |
|---|---|---|---|
| **B5** | 民主评议 vs 组织生活会(空答) | A 层,单 query 召回不到对照切片 | **Multi-Query / RAG-Fusion** > Hybrid Search > BCEmbedding |
| **A4/A5** | 八项规定数字题(具体数字答错) | A 层,dense embedding 不擅长数字 | **BM25 / Hybrid Search**(直接救星)> Reranker |
| **A7** | 党史教育评估每5年(答"无统一周期") | A 层,召回切片是泛泛描述 | **Reranker**(把含"5年"切片推上去) |
| **D1** | 培养联系人投票(答反) | **B 层,模型不采纳知识库** | **Strict Grounding Prompt**(直接救星) |
| **C3/D3** | 6 项议程顺序(答错) | 同 D1 | 同 D1 |
| **B6/B8** | V4 设计文档相关题(拒答) | 知识库根本没这些内容 | **入库 V4 文档** |

### 7.2 升级动作的优先级排序

按"工时 / 收益 / 跟自研算法重叠度"三维度综合:

| 优先级 | 升级动作 | 工时 | 工业验证收益 | 跟决策 1.6 自研算法重叠? |
|---|---|---|---|---|
| 🥇 P0 | **Strict Grounding Prompt**(改提示词) | 1 小时 | +5-10 点 | 不重叠,纯 Prompt 工程 |
| 🥇 P0 | **加 Reranker**(BCE 或 BGE) | 半天 | +10-15 点 | 部分重叠(决策 1.6 子模块 5) |
| 🥇 P0 | **Hybrid Search**(BM25 + Dense + RRF) | 1 小时(Dify 内置) | +5-10 点 | 不重叠 |
| 🥈 P1 | **换 Embedding(BCE)** | 半天 | +3-10 点 | 部分重叠 |
| 🥈 P1 | **Query Rewriting / Multi-Query** | 半天 | +5-15 点 | 不重叠 |
| 🥉 P2 | **Contextual Retrieval**(Anthropic 方法) | 1-2 天 | 不稳定 | 严重重叠(决策 1.6 子模块 3) |
| 🥉 P2 | **Structure-aware Chunking**(B站方法) | 1-2 天 | 不稳定 | 严重重叠(决策 1.6 子模块 1+2) |
| 🥉 P2 | **GraphRAG** | 3+ 天 | 多跳推理强 | 超出决策 1.6 范围 |

### 7.3 区分线:Day 3-7 做 vs Day 30+ 做

**Day 3-7 做的边界**:
- 不动文档清洗、切片策略——这部分留给自研算法
- 只用 Dify 内置功能 + Prompt 工程 + 外挂 Reranker
- 目的是**把"工业界标准动作"全打完**,作为自研算法的 baseline

**Day 30+ 做的边界**:
- 进入 Structure-aware Chunking、元数据增强、层次化检索
- 这部分是自研算法的核心贡献,论文上要讲清楚"为什么不直接用 B 站方法"

## 八、E5 系列子实验设计(从本文档导出)

### 8.1 子实验拆分

把原 E5 切片优化升级成四个独立子实验:

| 子实验 | 改动 | 工时 | 预期收益 | 当前位置 |
|---|---|---|---|---|
| **E5.1** | Strict Grounding Prompt | 1 小时 | +5-10 点,主治 D1/C3/D3 | 阶段 ⑤ |
| **E5.2** | 加 Reranker(BCE 或 BGE) | 半天 | +10-15 点 | 阶段 ④ |
| **E5.3** | Hybrid Search(BM25 + Dense) | 1 小时 | +5-10 点,主治 A4/A5 | 阶段 ③ |
| **E5.4** | 换 BCEmbedding | 半天 | +3-10 点 | 阶段 ③ |

### 8.2 实验顺序的考量

**推荐顺序**:E5.1 → E5.2 → E5.3 → E5.4

理由:
1. **E5.1 最便宜且独立**——只改 Prompt,先把这层"模型不采纳"的钱赚到
2. **E5.2 收益最大**——加 Reranker 工业界普遍 +15 点,先拿这个保底
3. **E5.3 治数字题**——BM25 对 A 类数字题立竿见影
4. **E5.4 最贵**(要起本地服务)且收益不确定——压到最后做

**实验对照纪律**:
- 每个子实验**只改一个变量**,保持其他配置不变
- 用同一份测试集 v1,保持评分标准一致
- 每轮 30 题跑完出 markdown 报告

### 8.3 预期累积收益

按工业界经验"取每步收益的一半"保守估算:

| 节点 | 累积准确率 |
|---|---|
| E4.3(当前) | 48.3% |
| +E5.1(Strict Prompt) | ~53% |
| +E5.2(Reranker) | ~60% |
| +E5.3(Hybrid Search) | ~65% |
| +E5.4(BCEmbedding) | ~68% |

如果 Day 7 能跑到 65%+,**就达到 RAG 实验设计 v1 的预期上限**(65-80%),
可以收口进入 Day 8+ Chatflow 多分支路由。

## 十、不在本文档范围内的方法

避免范围蔓延,以下方法**本文档不展开**(可在 Day 30+ 或论文撰写阶段再调研):
- **Fine-tuning embedding models**(领域微调 embedding):需要标注数据,工程量大
- **Knowledge Distillation for RAG**:跟主线无关
- **Multi-modal RAG**(图文混合检索):党务文档以文本为主,暂不需要
- **Streaming RAG / Long-context RAG**:跟当前模型选型相关,留到 LLM 选型阶段
- **Agentic RAG**(LLM 当 agent 多轮检索):跟 Dify Agent 节点的关系待理清
